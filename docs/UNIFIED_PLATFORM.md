# واجهة مقعد الموحدة

تستخدم صفحات الشركة القائمة الجانبية الفعلية من واجهة المقاعد الأصلية وأيقوناتها ونظام ألوانها. تتوفر الفعاليات والقاعات والموظفون والصلاحيات والاستيراد مع روابط مباشرة إلى مساحة تنظيم كل مخطط. بعد الدخول، تعرض لوحة الشركة بطاقات المخططات؛ الشركة الجديدة تبدأ بإنشاء فعالية وقاعة ومخطط دون إنشاء بيانات افتراضية.

داخل مخطط مقعد، يظهر اسم الشركة والمخطط الحالي وخيار التبديل بين المخططات وتسجيل الخروج. روابط الموظفين والاستيراد وإدارة المنصة تستخدم الجلسة نفسها والشركة المختارة. تتغير عبارات الحفظ المحلي إلى الحفظ داخل الشركة. تبقى نسخة المتصفح المحلية مستقلة ولا يُستبدل محتواها عند فتح بيانات الشركة.

لا توجد ترحيلات قاعدة جديدة أو تغييرات على RLS والحجوزات. وضع pilot الحالي يبقى مقيدًا بحساب المالك؛ دمج الواجهة لا يفتح التسجيل العام ولا يتجاوز متطلبات نطاق البريد. لا تغيّر DEPLOYMENT_MODE أو مفاتيح Render لتفعيل هذا التحديث؛ يكفي نشر أحدث commit من render-setup. لم تتغير ملفات النسخة المنشورة على GitHub Pages.

التحقق: اجتازت اختبارات الخادم الـ39. اختبار المتصفح email-login-browser.cjs يعمل في pilot وباستخدام BROWSER_HOSTED_MODE=beta مع رسائل محاكاة ونقل HTTPS معترض داخل الاختبار: التسجيل ورمز الدخول، إنشاء فعالية وقاعة ومخطط، فتح واجهة المقاعد، إضافة ضيف واستعادته بعد التحديث، الانتقال للموظفين والعودة للمقاعد، وقائمة الجوال دون تمرير أفقي. نجح أيضًا اختبار account-browser.cjs للمصادقة والاستعادة. لا تثبت محاكاة البريد تسليم رسائل حقيقية من Render.
