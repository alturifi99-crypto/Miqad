# أول نشر على Render

نشر لتجهيز الاستضافة فقط، وليس إطلاق SaaS أو نقل البيانات. استخدم الفرع `render-setup`، واترك Root Directory فارغًا. Build Command: `npm --prefix server ci`، Start Command: `node server/src/main.mjs`. المنطقة Frankfurt والخطة Free.

| المفتاح | القيمة |
| --- | --- |
| NODE_VERSION | 22 |
| NODE_ENV | production |
| DEPLOYMENT_MODE | setup |

يحدد Render المنفذ وRENDER=true، ويستمع الخادم حينئذ على 0.0.0.0. فحص الصحة `/api/health` يصرح mode=setup وproductionReady=false. صفحة البداية عربية توضح استمرار التجهيز، ومسارات الدخول والشركات والأسرار محجوبة. وضع التجهيز لا يحتاج اتصال قاعدة. لا تستخدم development لتجاوز حاجز الإنتاج. أوقف Auto-Deploy لحين مراجعة التفعيل. يتضمن render.yaml إعدادات مكافئة للإنشاء عبر Blueprint.

قاعدة التجربة المجانية تنتهي حسب التنبيه الظاهر في 21 نوفمبر 2026؛ لا تنقل إليها بيانات فعلية. لم تُختبر بعد صلاحية حساب Render لإنشاء أدوار المشروع. يجب التحقق منها وإنشاء أدوار التطبيق والمصادقة والمنصة المقيدة قبل الربط، دون تشغيل الشركات بحساب مالك الجداول.

المتبقي: إعداد أسرار الاتصال داخل Render، الترحيلات والتحقق من RLS والأدوار، تأكيد البريد والاستعادة وMFA للإدارة، إعداد الجلسات وHTTPS، ثم اختبارات العزل على الاستضافة. تغيير DEPLOYMENT_MODE وحده لا يفعّل الإنتاج؛ يبقى حاجز التطبيق قائمًا.

لا تعلن نجاح النشر قبل Live وفحص الصحة وصفحة البداية الفعلية. فرع التجهيز لا يغير GitHub Pages.

## فحص الاتصال أثناء التجهيز

بعد إضافة DATABASE_ADMIN_URL سرًا داخل Render، يفحص الخادم الاتصال مرة واحدة عند التشغيل باستخدام SELECT 1 واتصال للقراءة فقط بمهل محددة، ثم يغلقه. لا ينشئ جداول أو أدوارًا ولا يعدّل البيانات. تظهر نتيجة عربية على صفحة البداية، وتتوفر النتيجة المفلترة في `/api/setup/database`. لا تعيد الطلبات العامة فتح اتصال بالقاعدة، ولا تتضمن النتيجة رابط الاتصال أو اسم المستخدم أو أخطاء المشغل الأصلية. فشل الفحص لا يسقط صفحة التجهيز ولا يجعل فحص حياة الخدمة يشير إلى نجاح قاعدة البيانات. لا تزال جاهزية الإنتاج false، ولا يعني connected تطبيق الترحيلات أو التحقق من RLS على Render.

بعد تغيير متغيرات الاتصال، أعد نشر الخدمة لتحديث نتيجة الفحص المحفوظة في الذاكرة. لم يُتحقق من اتصال قاعدة Render من بيئة التطوير؛ يُقرأ نجاحه من النسخة المستضافة بعد النشر.

## التحقق من إمكانية التهيئة على الحساب المُدار

تحت نتيجة الاتصال، يفحص الخادم للقراءة فقط صلاحية إنشاء الأدوار ومتطلبات مالك الترحيلات الحالية، ثم إصدارات الترحيلات وأعلام FORCE RLS والأدوار إن كانت المتطلبات متوفرة. لا يعرض أسماء حسابات أو تفاصيل أخطاء أصلية. عدم السماح بإنشاء الأدوار يظهر كـrole_creation_unavailable؛ وجود CREATEROLE دون صلاحية المالك التي تعتمد عليها دالة miqad_can الحالية يظهر managed_owner_review_required. لا يعني هذا أن Render لا يدعم RLS، بل أن استراتيجية ملكية الدالة الحالية تحتاج تكييفًا واختبارات قبل تطبيقها بحساب غير متجاوز لـRLS. لا تُمنح BYPASSRLS لأدوار التطبيق كحل.

لم ينفذ هذا الفحص ترحيلات Render. schema_checks_passed يعني اجتياز فحوص بنيوية أولية فقط، وليس اختبار عزل فعلي على الاستضافة. إذا كانت الصلاحيات غير كافية، يلزم مسار مدعوم لإنشاء الأدوار أو تكييف البنية قبل متابعة الترحيلات. تبقى عمليات التسجيل وبيانات الشركات مغلقة.
